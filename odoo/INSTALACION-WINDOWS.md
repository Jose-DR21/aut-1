# Instalación nativa de Odoo 18 Community — laboratorio Windows

Alternativa oficial sin WSL 2 ni Docker, documentada por Odoo: https://www.odoo.com/documentation/18.0/administration/on_premise/packages.html#windows . Odoo advierte que Windows sirve para pruebas o instancias locales monousuario, **no** para despliegue productivo. Nuestro proyecto es una simulación local.

1. Descargar el instalador de versión seleccionada: https://nightly.odoo.com/18.0/nightly/windows/odoo_setup_18.0.20260928.exe (comprobado HTTP 200 el 2026-09-28; tamaño anunciado 322964744 bytes). No guardar el ejecutable en el repositorio. Registrar hash SHA-256 del ejecutable descargado antes de ejecutarlo: `Get-FileHash <ruta> -Algorithm SHA256`.
2. Ejecutarlo en **el mismo equipo** con permisos de administrador y aceptar UAC. Esta sesión no dispone de elevación. Si el instalador ofrece otro servidor PostgreSQL, no añadirlo sobre el puerto 5432 existente. Si instala su propio servidor en otro puerto, documentar el puerto real y configurar Odoo; no asumir que usa el existente.
3. PostgreSQL existente comprobado: 18.6 en `127.0.0.1:5432`. El usuario `postgres` autentica, pero para Odoo es preferible crear un rol dedicado con LOGIN y CREATEDB y una contraseña aleatoria local; no registrar esa contraseña aquí. Ejemplo después de crear una contraseña segura: `CREATE ROLE odoo_lab LOGIN CREATEDB PASSWORD '<secreto-local>';` desde `psql` como administrador. Ajustar el archivo de configuración local de Odoo con `db_host = 127.0.0.1`, `db_port = 5432`, `db_user = odoo_lab`, `db_password = <secreto-local>`, `http_interface = 127.0.0.1`, `http_port = 8069`. Mantener el archivo de configuración y credenciales fuera del repositorio.
4. **Hallazgo de instalación en este equipo:** el asistente de Odoo 18 creó `audit_sim` con `LC_COLLATE=C` y `LC_CTYPE=Spanish_United States.1252`; PostgreSQL 18 para Windows rechaza esa combinación. Se corrigió únicamente la base recién creada e inutilizable: `DROP DATABASE audit_sim WITH (FORCE)` y `CREATE DATABASE audit_sim OWNER openpg TEMPLATE template1` (locale y ctype coincidentes). Después se inicializó con el Python incluido: `python.exe server/odoo-bin -c server/odoo.conf -d audit_sim -i base --stop-after-init --no-http --data-dir <directorio-local>`; ver logs en directorio local, nunca repetir si la base ya tiene datos. No borrar ni recrear una base del usuario.
5. El servicio Windows usa `data_dir` protegido en Program Files, mientras el proceso CLI ejecutado sin elevación usa un directorio local con su *filestore*. Para usar los archivos generados por CLI sin elevar permisos se inicia otra instancia local en `127.0.0.1:8070` con ese mismo `data_dir` y los mismos complementos; el servicio en 8069 puede seguir encendido. Esta instancia adicional es sólo para la simulación, nunca se expone a Internet.
6. Comprobar versión, `audit_sim`, aplicaciones `stock` y `account`, menús y funciones realmente disponibles. No ejecutar `odoo/seed/seed.py` antes de verificar módulos. Ejecutar el cargador con el Python incluido, anotar IDs reales y capturas antes de sustituir valores planificados de los anexos.

**Nota:** el password compartido para el rol `postgres` se utilizó sólo para comprobar conectividad; por prudencia conviene rotarlo y usar otro distinto para `odoo_lab`. Ninguna credencial debe entrar en el repositorio ni aparecer en las capturas.
